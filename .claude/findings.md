- 2026-09-18: RESOLVED — both AcceptInvitationTest findings above (2026-09-17). Root cause was neither a flake nor a transaction-timing race: RefreshDatabase::beginDatabaseTransaction() rebinds db.transactions and hands the new manager only to the connections it transacts (the default one), so the already-resolved central connection kept the old manager while the event dispatcher read the container's. Every ShouldDispatchAfterCommit event raised inside a central transaction therefore fired immediately in tests. TestCase::shareOneTransactionManager() re-points every resolved connection at the container's manager after parent::setUp().
