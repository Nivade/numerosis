# PHPStan

- **Level 9 run over `app/` and `tests/` both — no per-path scoping.** `phpstan.neon` set global `level: 9` over `paths: [app/, tests/]`; `tests/` not pinned lower. `phpstan-baseline.neon` (44 entries) grandfathers violations existed when written. Don't assume green run = zero level-9 violations — check baseline size, not just exit code. Shrinking it ordinary cleanup, not prereq for anything (see `.claude/rules/testing.md`).

- **Run currently red, been so while — `vendor/bin/phpstan analyse` exits non-zero on `master`.** Measured 2026-07-31: **98 file errors, 9 under `app/`, 89 under `tests/`**, all *outside* 44-entry baseline. Matters procedurally: whole point of baseline is new errors fail immediately, that signal gone — red run no longer tells you your change broke something. **Before blaming PHPStan error on your work, diff count against `git stash`,** same way `.claude/rules/testing.md` says baseline suspicious test failure. One of 98 is `ignore.unmatched` on `tests/TestCase.php`, i.e. baseline itself drifted from code it describes.

  9 `app/` errors not 9 independent problems. Six one pattern: **`hasStripeId()` doesn't narrow `stripe_id` for PHPStan**, so `Cashier::stripe()->customers->retrieve($tenant->stripe_id)` reports `expects string, string|null given` even right after guard (`AddVatNumber`, `SyncBillingAddress`, every future action following same idiom). Fix that one narrowing — `@phpstan-assert-if-true` on `hasStripeId()`, or `stripeIdOrFail(): string` accessor on Billable concern — clears most of `app/` column in one change.

- **`treatPhpDocTypesAsCertain: false` deliberate, not level-9 side effect.** Docblock shape = claim about data, not runtime-enforced — several of ours describe JSON columns and webhook payloads nothing validates on way in. Left on, PHPStan treats defensive guard against documented shape as "always true" (dead code), pushes toward deleting the guard that's whole point. Native PHP types still treated certain; only level-9 mixed checks affected.

- **Mixed-typed blob consumed multiple places gets one shared type alias, not guard at every call site.** `Plan::metadata(): array<string, mixed>` forced every consumer re-narrow whatever pulled out. Fixed once as `PlanMetadata` type alias declared in `phpstan.neon`, shared by both `Plan` implementations and both consumers. New JSON/array blob gains second consumer add alias instead of duplicating narrowing logic — that duplication exactly what let two copies drift first place.

- **Read config through `Config::string()`/`array()`/`integer()`, not bare `config()`.** `config()` returns `mixed`; typed accessors fail loudly if key missing or wrong shape instead silently propagating `mixed` level 9 then flags at every downstream use. Also used in `LogoutUser` per `.claude/rules/auth-guards.md` — same reasoning, same pattern, use anywhere key known exist.

- **Two behaviour changes shipped as side effect chasing type errors, not separate bug fixes — both worth knowing if either area misbehaves.** `UpdateUserStatus` used swallow missing tenant id, broadcast empty string; now fails loudly instead. `PruneOrphanedTenantDatabases` used coerce unreadable schema name; now skips names it can't prove strings — since issues `DROP DATABASE`, unrecognised value must fall out of orphan list, never into it.
